# mathSXNU · 课堂信号

面向高等数学课堂的轻量网页应用。学生通过红、黄、绿三种信号反馈理解程度；教师查看实时汇总、阅读困难说明并导出教学记录。

**登录后没有进入课堂？[登录跳转修复与服务器更新步骤](docs/登录跳转修复更新.md)。** 修复课堂地址丢失、错误角色入口和重复显示登录页的问题；不修改数据库结构。

**已有网站更新师生注册功能：[按这份更新教程操作](docs/师生注册功能更新教程.md)。** 原有账号和课堂保留，学生反馈从浏览器会话升级为按登录账号去重。

## 已实现

- 注册登录：教师和学生可在前端分别注册，使用统一登录入口；教师管理自己的课堂，学生在“我的学习”查看已加入课堂。
- 学生：注册并登录后用6位课堂码 / 二维码进入；选择“听懂了 / 有点疑惑 / 需要帮助”，可选填300字说明。
- 状态更新：同一账号在同一课堂只保留一份当前状态，换浏览器或设备仍不重复；变更历史单独保存，相同内容重复提交不重复记历史。
- 教师：账号登录、创建多个课堂、每5秒刷新人数和比例、环形图、学生困难说明、结束和重新开放课堂。
- 数据：SQLite持久化、当前快照和变更历史CSV导出、数据库在线备份命令。
- 页面：中文界面，手机和电脑自适应；图表与二维码本地生成，无第三方CDN或AI调用。
- 部署：Docker与Compose配置、HTTPS反向代理、数据持久卷、健康检查、服务器备份脚本；连续5次登录失败后该账号冷却10分钟。

**学生反馈与账号关联。账号未经实名核验，一个人仍可能注册多个账号，不用于严格考勤或成绩评定。** 学生无法查看教师看板；仅本课堂的创建教师可读取统计、文字和导出。看板和CSV不显示学生用户名，管理员可通过数据库关联账号，不承诺完全匿名。

升级前的不记名反馈和变更历史全部保留，不会擅自绑定到新账号；看板与导出标注历史和账号记录的区别。

## 第一次运行（Linux / macOS，Python 3.12）

在本项目目录打开终端，依次运行：

```bash
bash scripts/setup.sh
.venv/bin/python manage.py createsuperuser
bash scripts/start.sh
```

第二条命令可用于开通首个维护账号；普通教师和学生现在也可以直接从网页注册，不必逐人运行该命令。密码输入时不会显示字符，没有通用默认密码。

启动成功后，按终端提示使用本机浏览器访问8000端口。首页右上角选择“注册”创建教师或学生账号；已有账号点击“登录”。教师创建课堂后即可获得课堂码和二维码。开发服务器用于本机验证，不要直接作为公网生产服务。

如需同一校园局域网内手机试用，应先确认学校网络允许互访，并将电脑局域网IP加入允许的主机名：

```bash
export DJANGO_ALLOWED_HOSTS='localhost,127.0.0.1,你的实际局域网IP'
bash scripts/start.sh
```

教师应从可被手机访问的局域网地址进入教师端，再生成课堂链接与二维码。若从本机回环地址进入，二维码也会包含本机地址，学生手机无法使用。局域网HTTP仅适合受控的短期测试；正式使用须部署HTTPS。

## 一次课堂怎样使用

1. 教师登录，点击“创建课堂”；例如课程填“高等数学”，课堂填“连续与可导的关系”。
2. 将二维码投屏，或把学生链接发到学习通。学生注册或登录后会返回该课堂，也可以从“我的学习”输入6位课堂码。
3. 学生选择一个信号并提交。理解变化后可重新选择和更新，同一账号当前汇总不会因此多计一份。
4. 教师看板约5秒更新一次；掉线时会明确提示旧数据，不伪装为实时数据。
5. 结束后导出当前反馈及需要的历史记录，点击“结束本次收集”。已有数据保留，下一次课另建课堂。

反馈原文可能含学生自己填写的个人信息，导出后请脱敏再用于评审。截图、演示数据和真实教学数据必须分开。

## 数据、备份与验证

```bash
# 运行功能与权限测试
.venv/bin/python manage.py test
# 检查模型与迁移一致
.venv/bin/python manage.py makemigrations --check --dry-run
# 在线备份数据库
.venv/bin/python manage.py backup_classroom
```

开发数据库位于 `.local/db.sqlite3`，开发密钥位于 `.local/secret_key`，均被Git忽略。删除数据库会丢失课堂、反馈、教师账号和会话，不能靠重启恢复。GitHub保存源码、部署文件和教程，运行数据库、备份、密码与 `.env` 不随源码上传。

备份命令生成 `.local/backups/` 中的文件。应将备份安全保存到另一台设备，妥善管理访问权限。恢复方法和生产部署见 [运行与部署说明](docs/运行与部署说明.md)。

## 可选浏览器端到端验证

需额外有 Playwright Python 包和 Chromium。本次环境已提供这两项，使用系统Python执行：

```bash
python3 scripts/browser_smoke.py
```

其他开发机可在独立测试环境安装Playwright并通过 `CHROMIUM_PATH` 指向实际Chromium可执行文件。脚本使用临时数据库和临时教师账号，不修改日常课堂数据；截图写入 `.local/screenshots/`，其中所有反馈均为演示数据。测试启动自己的临时Gunicorn进程，结束后关闭。

容器测试可在已构建 `mathsxnu-classroom:local` 镜像后运行 `python3 scripts/container_smoke.py`，使用独立的临时测试数据卷。GitHub Actions配置了Linux、Windows、macOS功能测试与容器构建；请查看实际Actions结果，配置存在不代表测试已通过。
