# 注册、登录后没有进入课堂：修复与更新

本次修复不修改数据库结构，不需要重新注册账号或重新配置域名。

用户进一步确认使用HTTP公网IP且教师、学生都停留登录页。这种情况还涉及安全Cookie与访问协议不一致，单独更新跳转逻辑不够，请优先按照[HTTP公网IP登录修复](HTTP公网IP登录修复.md)操作。

## 已复现并修复的路径

- 从课堂二维码进入登录页，再点击顶部通用“注册”，可能丢失课堂地址；现在会保留原课堂。
- 登录携带的旧地址是登录/注册页面时，可能登录后仍停在这些页面；现在只接受合法的课堂或角色入口。
- 学生从教师入口登录，可能被带去教师页并显示权限提示；现在回到学生入口。
- 已登录用户再次打开登录页，原来仍显示登录表单；现在直接进入对应入口或指定课堂。
- 教师从自己课堂的学生链接登录，现在直接进入该课堂教师看板；其他教师的课堂不会因此获得访问权限。

上述是开发环境已复现的问题，未连接用户线上服务器进行诊断。若线上出现会话Cookie或HTTPS配置问题，还需根据实际访问地址与错误信息检查。

## 更新后正确的行为

| 操作 | 应进入的页面 |
| --- | --- |
| 教师直接注册/登录 | 我的课堂 |
| 学生直接注册/登录，没有课堂链接 | 我的学习，可输入课堂码或选择已加入课堂 |
| 学生通过二维码/课堂链接注册或登录 | 该课堂反馈页面 |
| 已登录后再次打开登录页 | 对应入口或有效的目标课堂，不再重复显示登录表单 |

学生没有指定课堂时，系统不会随意选择其他老师的课堂。新教师尚未创建课堂时，看到“创建我的第一个课堂”是正常情况。

## 在原服务器更新

选暂时不使用网站的时间，打开原服务器的远程终端。以下代码逐组执行，前一组成功再继续。

1. 进入原目录并备份：

   ```bash
   cd /opt/mathsxnu
   sudo bash scripts/backup-server.sh
   ```

2. 下载修复：

   ```bash
   sudo git pull --ff-only origin main
   ```

3. 构建新版程序：

   ```bash
   sudo docker compose build web
   ```

4. 重新启动新版并等待健康检查：

   ```bash
   sudo docker compose up -d --no-build --wait --wait-timeout 180
   sudo docker compose ps
   ```

不要删除 `.env`、数据库或数据卷，不执行 `docker compose down -v`。若构建或启动失败，停止后续操作，保留错误提示。

## 检查修复

1. 电脑浏览器打开原来的HTTPS课堂域名，按 `Ctrl+F5` 刷新。
2. 用教师账号登录，应进入“我的课堂”；已登录后再次打开登录页，也应进入课堂入口。
3. 手机在未登录状态下打开课堂二维码，点击顶部“注册”，选择学生身份，注册成功后应回到该课堂。
4. 学生退出后再次用同一课堂链接登录，仍应回到该课堂。
5. 从首页单独登录学生账号，应进入“我的学习”；没有加入的课堂时需要输入老师提供的课堂码。

如果仍然回到登录表单，请记录：教师还是学生账号、地址栏是HTTP还是HTTPS、登录后显示的页面或错误文字。正式站点使用已配置好的HTTPS域名；若当前只有HTTP公网IP且仅做功能试用，应按专门教程统一配置协议和Cookie，不要只零散关闭某一项设置。
