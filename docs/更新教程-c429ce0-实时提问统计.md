# c429ce0 专用更新教程：疑惑、求助与追问实时统计

目标功能版本：`c429ce0260c5e5934a470aee08b972d8e4a439dc`。本页为这次版本单独编写，不套用旧版编号。支持服务器从 `7bf829c` 或 `9c3c36d` 更新，已为 `c429ce0` 时无需再次导入。本次不新增数据库迁移。

更新后“有点疑惑”和“需要帮助”分别显示当前人数、累计提问人数/次数、已解决/待答次数。同一学生追问增加一次提问，人数不重复增加；同一问题多次回复只算解决一次。已解决以教师回复为准。统计约每5秒更新，与分页无关。

## 路线选择

- GitHub连接正常：按原教程备份，再正常拉取、构建与重启。
- GitHub连接超时：使用本页推荐的专用离线更新文件，在电脑下载并上传服务器，不再让服务器反复连接GitHub。

## 第1步：在电脑下载本版离线更新文件

[下载 import-update-c429ce0.py](https://raw.githubusercontent.com/SXNUHyx/mathSXNU/main/scripts/import-update-c429ce0.py)

这是HTTPS链接。若浏览器显示代码，右键另存为，文件名保持 `import-update-c429ce0.py`，不要变为 `.py.txt`。此文件约19KB，内含经过校验的本版Git更新数据，**不需要另下ZIP或bundle**。只从本仓库下载，不用旧版导入脚本。

若仅需查看或归档源码，可另下载 [c429ce0源码ZIP](https://github.com/SXNUHyx/mathSXNU/archive/c429ce0260c5e5934a470aee08b972d8e4a439dc.zip)；不要直接解压覆盖生产目录。

## 第2步：上传到腾讯云

在腾讯云服务器“文件管理”进入 `/root`，上传下载的 `.py` 文件。终端仍使用Ubuntu账号，读取root目录文件时加sudo。不要把路径单独当作命令执行。

```bash
sudo ls -lh /root/import-update-c429ce0.py
cd /opt/mathsxnu
sudo git log -1 --oneline
sudo git status --short
sudo docker compose ps
```

本地修改列表应为空，服务应为原部署的web和gateway。若路径、版本或服务不一致，先核对，不能强制重置或覆盖。

## 第3步：校验下载文件并检查版本

下面命令应输出 `OK`：

```bash
echo 'c16d7a12323b351711c8176de5584f34bad33b0b84202eb93cbdf3c67f4a7f8f  /root/import-update-c429ce0.py' | sudo sha256sum -c -
```

校验失败时停止，不执行文件，重新从上面的官方链接下载。成功后运行只读预检查：

```bash
sudo python3 /root/import-update-c429ce0.py --check
```

应显示可以从7bf829c或9c3c36d更新到c429ce0，或已是目标版本。其他版本、存在本地修改或校验失败均会停止，不覆盖项目文件。该预检查不导入代码。

## 第4步：先备份数据库与课程资料

```bash
sudo bash scripts/backup-server.sh
```

看到数据库和资料备份成功提示再继续。备份失败先停止。本更新保留原 `.env`、Docker卷、账号和课程数据，不运行首次部署向导，不改域名或HTTP/HTTPS设置。

## 第5步：离线导入本版代码

```bash
sudo python3 /root/import-update-c429ce0.py
sudo git log -1 --oneline
sudo git status --short
```

预期显示“离线代码更新完成：c429ce0”，日志是c429ce0，Git状态无输出。脚本校验内嵌更新数据，通过本地Git bundle和快进合并保留原提交历史；这一阶段无需连接GitHub。再次运行会识别目标版本并退出。

## 第6步：构建新版镜像

```bash
sudo docker compose build web
```

等待成功再继续。镜像构建仍可能需要访问Docker/PyPI等依赖源；失败时先保留错误排查，不替换原服务。

## 第7步：暂停入口并再次备份

```bash
sudo docker compose stop gateway
sudo bash scripts/backup-server.sh
```

第二次备份成功再启动新版。如果备份失败且尚未替换web，执行 `sudo docker compose start gateway` 恢复旧入口，停止升级。

## 第8步：启动并检查

```bash
sudo docker compose up -d --no-build --force-recreate --wait --wait-timeout 180
sudo docker compose ps
sudo docker compose exec -T web python manage.py check
sudo docker compose exec -T web python manage.py migrate --check
```

预期web为healthy，gateway运行，Django检查通过，无待执行迁移。报错时运行 `sudo docker compose logs --tail=80 web gateway`，保留输出，不执行 `docker compose down -v`。

## 第9步：浏览器验收

1. 电脑Ctrl+F5刷新，手机关闭旧页面再打开。
2. 在测试课堂让测试学生提交一条有点疑惑，确认累计1人、1次、待答1次。
3. 老师回复，确认已解决1次、待答0次。
4. 同一学生再次追问，确认累计仍1人、提问2次、已解决1次、待答1次。
5. 对需要帮助模块执行相同测试；检查其他看板约5秒更新，不用真实课堂测试删除。
