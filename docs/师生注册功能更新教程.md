# 已有网站如何更新：加入教师注册和学生注册

适用情况：您已按原教程在国内Ubuntu服务器部署成功，项目目录是 `/opt/mathsxnu`，使用 `docker compose`，已有真实域名和课堂记录。

本次不需要重装服务器，不需要重新购买域名，也不需要重新生成 `.env`。代码从GitHub更新，数据库在原持久卷中升级。

新页面示例（虚构演示环境）：[教师注册](images/teacher-register-desktop.png) · [学生手机注册](images/student-register-mobile.png)。

## 更新后会有什么变化

| 对象 | 新功能 |
| --- | --- |
| 教师 | 点击“注册→我是老师”，在网页设置用户名和密码；自动登录后创建自己的课堂 |
| 学生 | 点击“注册→我是学生”，设置用户名和密码；在“我的学习”查看加入过的课堂及自己的反馈状态 |
| 登录 | 教师和学生共用“登录”入口，系统自动判断身份 |
| 反馈 | 必须用学生账号登录；同一账号换浏览器或换手机只计一份当前反馈 |
| 权限 | 学生不能创建课堂、查看班级看板或导出；不同教师仍不能读取彼此课堂 |
| 原教师 | 账号、密码、教师身份及原课堂保留，不用重新注册 |
| 原反馈 | 历史不记名记录保留，不能自动认领给新账号；看板和CSV区分新旧来源 |

教师注册是开放的，不代表系统核验了教师任职资格。新注册教师不是平台管理员，只能管理自己创建的课堂。学生账号也未经实名核验，仍不作为严格考勤依据。

反馈从本次更新开始与账号关联，不再是完全不记名的浏览器反馈。看板和CSV不展示用户名，但管理员可通过数据库追溯，教师可以读取留言。通知学生时应说明这一变化。

## 第1步：选一个暂时没有上课的时间

先告诉正在使用平台的老师和学生：“平台将短暂停止访问，加入注册功能，请稍后再反馈。”

构建程序时旧网站还能使用；正式迁移时会短暂停站。下面每个代码框逐组执行，上一组成功后再执行下一组。

## 第2步：进入原服务器的终端

1. 登录您原来的云平台控制台。
2. 找到之前部署网站的那台服务器，不要新建服务器。
3. 点击“登录 / 远程登录”，打开与原教程相同的浏览器终端。
4. 下面的命令全部输入在这个服务器终端，不是在Windows搜索框，也不是在GitHub网页上输入。

先执行：

```bash
cd /opt/mathsxnu
sudo docker compose ps
```

应该看到已有 `web`、`gateway` 服务。若提示目录不存在，说明您实际部署目录不同，先找到原目录再继续，不要新建空目录照着运行。

## 第3步：先备份原有课堂数据

```bash
sudo bash scripts/backup-server.sh
sudo git rev-parse --short HEAD
```

应该显示“备份完成”和备份保存路径；第二条显示当前旧版本编号。记下这两个信息，方便必要时排查。

备份在服务器的 `backups` 目录。还应通过您熟悉的安全文件下载方式保留到另一台设备。备份包含账号及学生留言，不上传GitHub。

**如果备份报错，就停在这里，先解决备份问题。** 此时网站仍在使用旧版。

## 第4步：从GitHub下载本次更新

```bash
sudo git pull --ff-only origin main
```

正常会列出更新文件，例如 `feedback/roles.py`、注册页面、数据库迁移和本教程。如果显示 `Already up to date`，表示本地已经同步，可以继续检查文件：

```bash
ls templates/register.html feedback/migrations/0004_preserve_existing_teacher_accounts.py
```

应能列出这两个文件。若提示Git冲突、认证失败或本地修改，保留错误信息，不执行强制覆盖，不删除原目录。

## 第5步：提前构建新版程序

```bash
sudo docker compose build web
```

这一阶段可能需要下载软件，等待命令完成并返回可输入状态。如果这里失败，不进行下一步停站，旧网站此时仍可继续运行。

## 第6步：短暂停站，再做最后一次备份

确认现在可以暂停网站后执行：

```bash
sudo docker compose stop gateway
sudo bash scripts/backup-server.sh
```

此时网址暂时不能打开，属于预期状态。应用容器仍在，备份脚本会把停站前的最新数据保存下来。

如果这次备份失败，还没有启动新版或迁移数据库，可先执行 `sudo docker compose start gateway` 恢复旧网站，然后处理备份错误，不继续更新。

## 第7步：启动新版，自动升级数据库

```bash
sudo docker compose up -d --no-build --wait --wait-timeout 180
sudo docker compose ps
```

新版启动时会自动执行 `migrate`，添加角色、学生课堂列表及账号反馈关联，保留原记录。命令成功后 `web`应为运行中并通过健康检查，`gateway`也应运行。

如果没有成功，查看：

```bash
sudo docker compose logs --tail=80 web gateway
```

此时不要删除数据库、重新生成密钥或强行回退迁移。保留日志中的错误信息，再按错误诊断；日志先检查是否含个人信息后再提供。

**不要执行 `docker compose down -v`，它会删除持久数据卷。** 本次升级不需要该命令。

## 第8步：确认数据库升级完成

```bash
sudo docker compose exec -T web python manage.py showmigrations feedback
```

应看到下面两项前面都有 `[X]`：

```text
[X] 0003_accountprofile_classroommembership_response_user_and_more
[X] 0004_preserve_existing_teacher_accounts
```

还可以检查程序配置：

```bash
sudo docker compose exec -T web python manage.py check
```

应显示未发现系统问题。数据库迁移失败时，不要跳过这一检查直接通知学生使用。

## 第9步：先检查您的旧教师账号

1. 在Windows浏览器打开原来的课堂网址，按 `Ctrl+F5` 强制刷新。
2. 如果原来已经登录，可以先检查“我的课堂”，再退出并重新登录一次。
3. 点击“登录”，用原用户名和密码登录。
4. 应进入“我的课堂”，看到原来的课堂。
5. 打开一个原课堂，核对反馈数量、留言和导出。

旧版全部已有账号会自动保留教师身份，不用再次创建管理员。历史不记名反馈不能可靠关联到新学生，因此会继续单独保存并标注。

## 第10步：测试一位新教师注册

使用浏览器隐私窗口，或先退出原账号：

1. 首页点击“注册”。
2. 点击“我是老师，创建课堂”。
3. 设置一个新的用户名，使用3—30位英文字母、数字或下划线。
4. 输入密码并再次确认。页面会说明密码要求；用户名已被使用会提示换一个。
5. 点击“注册教师账号”。
6. 注册成功后自动进入“我的课堂”，新账号应看不到原教师的课堂。
7. 创建一个标为“注册升级测试”的课堂，得到课堂码和二维码。

新增教师可以从网站自己注册，不需要进入服务器执行 `createsuperuser`。选择教师身份不会得到管理其他老师数据的权限。

## 第11步：测试学生注册和手机反馈

1. 安卓手机浏览器打开新测试课堂二维码或链接。
2. 未登录时先出现登录页面，点击“学生注册”。
3. 设置另一个未使用的用户名、密码、确认密码，点击“注册学生账号”。
4. 注册成功后应自动回到扫码进入的课堂。
5. 选择“需要帮助”，提交一句测试反馈。
6. 教师看板应在约5秒后显示一份反馈。
7. 手机顶部点击“我的学习”，应看到这个课堂和自己的反馈状态。

也可以从首页点击“学生注册”，注册后在“我的学习”输入6位课堂码加入。学生进入网址 `/teacher/` 时应看到身份提示，不应看到教师管理功能。

## 第12步：检查同一学生换设备是否重复计数

1. 在另一台电脑或手机登录刚注册的同一个学生账号。
2. 输入同一个课堂码，应该看到已经提交的状态。
3. 改为“听懂了”并更新。
4. 教师看板的新账号反馈仍只有一份，状态变为绿色；不会因为换设备而多计一个账号。

不要用带有历史不记名记录的课堂判断“总数必须等于1”；请使用第10步新建的空测试课堂。旧历史记录会保留并另外计入总反馈。

## 第13步：正式通知师生使用

检查旧账号、新教师注册、新学生注册和反馈流程均正常后，可以发送：

> 平台已增加账号注册。老师在首页点击“注册”，选择教师身份；学生选择学生身份。注册后自动登录，学生使用老师分享的课堂码或二维码进入。反馈会关联登录账号，同一账号换设备不会重复计入当前反馈。请记住用户名和密码，不在留言中填写个人隐私。

原教师账号无需重复注册。教师账号只用于教师功能，不能直接提交学生反馈；教师要演示学生提交流程时，使用独立的学生测试账号。

## 常见问题

- **刷新后仍看不到注册按钮：**先 `Ctrl+F5`，再确认更新的是原部署目录、拉取的是 `main`，并检查新容器是否启动；不要把清理数据当成刷新网页。
- **注册提示用户名重复：**教师和学生共用全站用户名空间；新用户名统一保存为小写，换一个即可。登录可使用唯一匹配的大小写形式，原有账号精确名称优先保留。
- **连续输错密码无法登录：**已有10分钟登录失败冷却；等待后再用正确密码，不反复重试。
- **忘记密码：**本版本未接入邮件或短信找回，由维护者执行 `sudo docker compose exec web python manage.py changepassword 用户名` 交互式重设。不要在命令或聊天中附上密码。
- **注册错了身份：**退出后使用另一个用户名注册正确身份。当前没有前端自行切换角色的入口，已有账号不通过修改网页请求变成另一种身份。
- **其他教师看不到我的课堂：**这是预期权限；不同教师数据隔离。协同授课授权不包含在本次功能内。
- **历史反馈为什么仍显示：**升级保留已有数据，没有证据可靠认领旧记录，不擅自删除或绑定学生账号。
