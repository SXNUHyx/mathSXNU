# 六项功能：课程学习、资料与定向答疑

后续已增加[免费可视化公式编辑和三个独立学习板块](可视化公式与三板块更新教程.md)。本文保留六项功能说明及旧配置备份步骤；当前模块布局和最新升级检查以新教程为准。

本次代码支持所有课程，不再将首页固定为高等数学。教师、学生均继续使用浏览器，原账号和课堂不需要重新创建。

## 功能与使用方法

### 1. 中文用户名注册

首页点击“注册”，选择教师或学生，用户名可填写“王老师”“张小明”等中文名字，也支持生僻汉字。用户名全站唯一，重名时可增加数字。英文字母不区分常见大小写形式，原有账号仍可登录。

注册用户名与提交反馈时的姓名分开：即使用户名是别名，反馈仍需填写本人姓名、学号。系统不提供学校实名核验。

### 2. 通用课程界面

首页显示“课程学习 · 课堂即时反馈”，新建课堂不再默认填高等数学。教师自定课程名称和课堂主题，旧课堂原本填写的课程名称保留。

### 3. 具名学生反馈

学生打开课堂，填写“姓名”“学号”，选择红黄绿信号并提交。姓名和学号会作为本次反馈的快照保存，并自动带入之后的反馈表单；学号开头的0不会丢失。

教师在课堂的“学生反馈与答疑”区域可看到姓名、学号、状态和问题。每页50份，可翻页查看所有反馈，统计图仍统计整堂课。CSV追加姓名、学号列，旧列顺序保留。

CSV原文保留学号开头的0；Excel直接打开时可能自动把学号转成数字。请通过“数据→从文本/CSV”导入，并将学号列设置为文本。

其他学生无法看到这些信息。旧记录缺少姓名、学号时按实际数据标注，不凭用户名编造真实身份；原来完全不记名的记录无法可靠找回学生，也无法定向回复。

### 4. 删除课堂与恢复

教师进入自己课堂，点击“删除课堂”，在确认页确认。课堂移入“课堂回收站”，学生无法再访问其资料、反馈和回复。

教师工作台点击“课堂回收站→恢复课堂”，原课堂码、资料和反馈保留。恢复后课堂保持结束状态，需要时再点击“重新开放课堂”。其他教师不能删除或恢复您的课堂。

这是可恢复的删除，不会释放资料磁盘空间；永久清理需要另由维护者处理。

### 5. 图片、课程资料与学习模块

教师进入课堂，点击“添加模块”，选择“知识点”“重点”或“难点”，填写标题、内容和排序。模块可编辑，较小的排序数值排在前面。

内容支持LaTeX数学公式，可直接输入或使用编辑器上的分式、积分、极限按钮，下面自动预览。例如：

```text
行内公式：\(E(X)=\sum_i x_i p_i\)

独立公式：
\[
\int_a^b f(x)\,dx
\]
```

公式使用本地KaTeX渲染，支持其LaTeX数学语法，不依赖外部CDN。文字不会当作HTML执行，复杂公式以预览支持结果为准。

点击“上传图片 / 资料”，填写名称、选择文件，可关联某个模块。关联的文件显示在模块下，未关联文件显示在“课程资料库”。图片在线查看，PDF和PowerPoint以下载方式提供，不包含在线PPT编辑器。

| 文件 | 大小与规则 |
| --- | --- |
| JPG、JPEG、PNG、WEBP | 每个最大5MB，检查真实图片格式，最多2500万像素 |
| PDF | 每个最大25MB，基础格式检查，作为附件下载 |
| PPT、PPTX | 每个最大25MB，基础容器结构检查；不接收PPTM宏文件 |

基础检查不等于病毒扫描，请上传可信教学文件。整次上传请求上限30MB，超限可能显示413，需要压缩或拆分。

资料没有公开的媒体目录入口：只有本课堂教师和已加入的学生能读取。课堂删除或资料移除后，原下载地址失效。学生已下载到设备上的副本无法远程撤回。

### 6. 定向解释与自动接收

教师在某份反馈下点击“回复这位学生”，输入解释，可使用LaTeX预览，点击“发送解释”。解释只发给该反馈对应的登录账号。

学生网页保持打开并处于前台时，约3秒检查一次新回复：在课堂的“老师的解释”区域显示内容，“我的学习”等页面也显示未读提醒。学生点击“标记以上回复为已读”后，教师能看到已读状态。

离线时解释保存在数据库，下次打开网页即可看到未读消息。本版本不是手机系统通知或短信推送，浏览器关闭时不会弹系统通知。

回复保存当时问题的快照。即使学生后来更新了问题，仍能知道解释针对哪一次反馈。

## 从现有服务器更新

### 先处理您之前的本地改动

您此前提供的服务器状态为旧版 `ba020ae`，并修改过 `compose.yaml`、`deploy/Caddyfile`、`mathsxnu/settings.py`。若仍如此，不能直接覆盖。若已经更新过且 `git status --short` 为空，可跳过暂存步骤，但仍需备份数据库。

在原云服务器终端执行：

```bash
cd /opt/mathsxnu
sudo git status --short
sudo docker compose exec -T web python -c "import os,django; os.environ.setdefault('DJANGO_SETTINGS_MODULE','mathsxnu.settings'); django.setup(); from django.conf import settings; print(settings.DATABASES['default']['NAME'])"
sudo docker inspect mathsxnu-classroom-web-1 --format '{{range .Mounts}}{{println .Type .Name .Destination}}{{end}}'
```

数据库应为 `/data/db.sqlite3`，挂载应含 `volume mathsxnu-classroom_classroom_data /data`。不一致时先停止更新，把这两项非敏感信息提供给维护者，避免换配置后读取到另一个空数据库。

备份数据库与已有课程资料：

```bash
sudo bash scripts/backup-server.sh
```

旧版没有资料库时只备份数据库，属于正常情况。已有资料库的新版本会额外生成资料压缩包。任一步备份失败，先停止更新。

如果仍只有上述三个文件有本地修改，先备份，再暂存：

```bash
task_backup_dir="/opt/mathsxnu-config-backup-$(date +%Y%m%d-%H%M%S)"
sudo mkdir -m 700 "$task_backup_dir"
sudo cp --parents compose.yaml deploy/Caddyfile mathsxnu/settings.py "$task_backup_dir"
sudo cp .env "$task_backup_dir/.env"
sudo git stash push -m "before-course-learning-upgrade" -- compose.yaml deploy/Caddyfile mathsxnu/settings.py
```

配置和密钥备份仅保存在服务器，不能上传GitHub。网站接下来使用新版统一配置，旧改动留在备份和服务器本地stash中，不直接回写旧配置。若出现其他未知文件改动，先保留并确认用途。

### 下载与启动新版

以下代码逐组执行，上一组成功后再继续。

1. 更新代码：

   ```bash
   sudo git pull --ff-only origin main
   ls feedback/migrations/0005_accountprofile_real_name_and_more.py
   ```

2. 若目前仍用HTTP公网IP功能试用，将 `YOUR_PUBLIC_IP` 换成自己的IPv4；已经正确使用HTTPS域名则保留原配置，跳过此条：

   ```bash
   sudo python3 scripts/set-access-mode.py --http-trial --host YOUR_PUBLIC_IP
   ```

   现在需要传输姓名、学号，请在正式收集真实学生信息前配置HTTPS；HTTP试用只使用模拟身份和测试账号。

3. 先构建，构建失败时保留旧服务，不继续停站：

   ```bash
   sudo docker compose build web
   ```

4. 在不进行教学的时间，暂停入口并做最后一次备份：

   ```bash
   sudo docker compose stop gateway
   sudo bash scripts/backup-server.sh
   ```

   备份失败且还没启动新版时，可用 `sudo docker compose start gateway` 恢复旧服务。

5. 启动新版，自动迁移数据库：

   ```bash
   sudo docker compose up -d --no-build --force-recreate --wait --wait-timeout 180
   sudo docker compose ps
   sudo docker compose exec -T web python manage.py showmigrations feedback
   ```

   需要看到 `web` 健康检查通过，以及 `[X] 0005_accountprofile_real_name_and_more`。本次保留原数据卷，新增的图片和资料保存在同一持久卷 `/data/media`。

6. 检查文件存储与登录配置：

   ```bash
   sudo docker compose exec -T web python -c "import os,django; os.environ.setdefault('DJANGO_SETTINGS_MODULE','mathsxnu.settings'); django.setup(); from django.conf import settings; print(settings.MEDIA_ROOT)"
   sudo docker compose exec -T web python manage.py check_login_access
   ```

   资料目录应为 `/data/media`。如果不是，不上传真实资料，先检查是否使用了新版Compose配置。

7. Windows浏览器按 `Ctrl+F5`，或使用新的隐私窗口打开站点，按照上面的六项操作方法验收。原账号继续使用，历史记录姓名学号为空是正常情况。

失败时查看 `sudo docker compose logs --tail=80 web gateway`，先隐藏个人信息再提供错误片段。不要删除原目录、数据库，不执行 `docker compose down -v`，也不要擅自逆向执行0005迁移。

## 备份和恢复交接

每次执行 `sudo bash scripts/backup-server.sh`，新版会保存两个文件：数据库 `.sqlite3` 与课程资料 `materials-*.tar.gz`。两者都应安全下载到另一台设备保存。单独备份数据库不能恢复图片和课件。

数据库保存姓名学号、反馈、教师回复、模块及文件索引；资料压缩包保存真实文件。恢复需在停止服务后使用匹配的数据库和资料备份，资料中的 `media/` 对应服务 `/data/media`。由维护者核对服务用户权限后再启动，不在运行中的数据卷上盲目解压或覆盖。

课堂或资料的可恢复移除不会立即删除私有磁盘文件，因此存储占用需要维护者定期检查。
