# 腾讯云 Ubuntu：MathSig 功能更新与已验证部署流程

本教程用于已按本仓库原教程部署、目录为 `/opt/mathsxnu` 的 Docker Compose 服务器。命令在腾讯云终端 `ubuntu@VM-0-11-ubuntu:~$` 后执行，**不要复制提示符本身**。每组命令成功后再进行下一步。选择没有上课的时间更新，切换容器时网页会短暂中断。

如果项目目录不同，使用原项目实际目录；不要重新克隆一份部署，不要重新运行首次部署向导，不要覆盖 `.env`。本次功能修改不新增数据库迁移；从更早版本升级时，容器仍会自动执行其尚未应用的迁移。

## 1. 进入原项目，确认部署与本地改动

```bash
cd /opt/mathsxnu
sudo git status --short
sudo docker compose ps
sudo docker compose exec -T web python -c "import os,django; os.environ.setdefault('DJANGO_SETTINGS_MODULE','mathsxnu.settings'); django.setup(); from django.conf import settings; print(settings.DATABASES['default']['NAME'])"
sudo docker inspect "$(sudo docker compose ps -q web)" --format '{{range .Mounts}}{{println .Type .Name .Destination}}{{end}}'
```

预期：`web` 和 `gateway` 存在；数据库路径为 `/data/db.sqlite3`；原数据卷挂载在 `/data`。保留该数据卷和原项目目录。

`git status --short` 没有输出才表示代码无本地修改。若有输出，先保留并核对这些文件，尤其是 `compose.yaml`、`deploy/Caddyfile`、`mathsxnu/settings.py`。可以提供文件名列表协助判断；不要发送 `.env` 内容。不要用 `git reset --hard` 丢弃服务器配置，也不要直接覆盖或自动套回旧配置。

若 `cd` 或上述检查失败，先解决目录或部署差异，不要继续后面的替换操作。

## 2. 备份数据库、上传资料与部署配置

```bash
sudo bash scripts/backup-server.sh
```

预期输出数据库 `.sqlite3` 和课程资料 `.tar.gz` 的备份位置，位于项目 `backups/`。任一步失败先停止更新。可将备份另行安全下载到自己的电脑，不要提交 GitHub。

另外保存当前代码版本与部署配置：

```bash
update_backup_dir="/opt/mathsxnu-update-backup-$(date +%Y%m%d-%H%M%S)"
sudo mkdir -m 700 "$update_backup_dir"
sudo cp --parents .env compose.yaml deploy/Caddyfile mathsxnu/settings.py "$update_backup_dir"
sudo git rev-parse HEAD | sudo tee "$update_backup_dir/previous-commit.txt"
echo "配置备份位置：$update_backup_dir"
```

这个目录包含私密配置，仅供服务器维护者使用。它不替代数据库及上传文件备份。

## 3. 拉取 GitHub 新代码：沿用本次服务器验证成功的 IPv4 流程

本服务器曾在普通 `git pull` 时连接 GitHub 443 超时，随后 `curl -4` 返回200，使用 `http.curloptResolve` 指定解析出的 IPv4 地址后更新成功。以后使用以下流程；参数仅本次生效，不更改全局Git配置或 `/etc/hosts`，保留HTTPS证书验证。

先检查IPv4访问与当前解析：

```bash
curl -4 -I --connect-timeout 10 --max-time 20 https://github.com
getent ahostsv4 github.com
```

第一条应返回200，第二条应显示IPv4。已验证时地址为 `20.205.243.166`；GitHub地址可能变化，所以每次使用当前解析值，不永久固定旧地址。上面检查成功后，在同一终端整段执行：

```bash
github_ipv4="$(getent ahostsv4 github.com | awk '$2 == "STREAM" {print $1; exit}')"
if [ -n "$github_ipv4" ]; then
    sudo git -c "http.curloptResolve=github.com:443:$github_ipv4" pull --ff-only --progress origin main
else
    echo '未解析到GitHub IPv4，停止更新，请保留错误信息。'
fi
```

确认拉取成功后检查版本与文件：

```bash
sudo git log -1 --oneline
ls templates/developer_lessons.html feedback/test_course_management.py
```

两份文件都应存在。若提示本地改动冲突、分支分叉或权限错误，不要继续；保留输出进行排查。不要使用强制重置。

完整教程也可在服务器查看：

```bash
less docs/课程管理与反馈分组更新教程.md
```

按 `q` 退出阅读。

## 4. 构建新网页镜像

```bash
sudo docker compose build web
```

必须等待构建成功再继续。构建期间旧网站仍可服务。此过程保留原 HTTP/HTTPS、域名、端口和 `.env` 设置；无需重新配置访问模式。若因镜像仓库或依赖下载失败，保留错误信息先排查，不关闭 TLS 验证。

## 5. 暂停访问入口，再备份一次

```bash
sudo docker compose stop gateway
sudo bash scripts/backup-server.sh
```

第二次备份纳入构建期间新增的反馈和上传资料。若此处备份失败，尚未替换 `web` 时可执行下列命令恢复旧入口，然后停止升级并排查：

```bash
sudo docker compose start gateway
```

## 6. 启动新版并检查

仅在第5步备份成功后执行：

```bash
sudo docker compose up -d --no-build --force-recreate --wait --wait-timeout 180
sudo docker compose ps
sudo docker compose exec -T web python manage.py check
sudo docker compose exec -T web python manage.py migrate --check
sudo docker compose exec -T web python manage.py check_login_access
sudo docker compose exec -T web python -c "import urllib.request; r=urllib.request.urlopen('http://127.0.0.1:8000/health/',timeout=5); assert r.status == 200 and r.read() == b'ok'; print('health: ok')"
```

预期：`web` 为 `healthy`，`gateway` 正在运行，Django 检查无问题，没有待应用迁移，最后显示 `health: ok`。`check_login_access` 用于核对原登录访问配置，其提示结合实际 HTTP/HTTPS 使用方式判断。

若 `--wait` 被旧版 Compose 提示不支持，先检查 `sudo docker compose version` 并更新 Compose 插件后继续，不要把未知结果当作启动成功。

若启动或检查失败，收集日志：

```bash
sudo docker compose logs --tail=80 web gateway
```

不要执行 `docker compose down -v`，不要删除数据卷、数据库或备份，不要盲目反向迁移或重复重建。保留报错和第2步的原版本信息；分享日志前遮住个人资料和密钥。

## 7. 用开发者管理员登录

在浏览器打开原网站，使用已有开发者管理员登录，进入“开发者管理 → 课程管理”，或访问原网址后加 `/developer/lessons/`。

如果自己的账号还没有开发者权限，用下面命令为**自己实际登录的用户名**开通，替换引号中的文字：

```bash
sudo docker compose exec -T web python manage.py grant_platform_admin --username "你的实际登录用户名"
```

此命令会启用该账号并赋予开发者管理员权限，保留原密码和课堂。只为应当具有全站管理权限的账号执行。然后退出网页重新登录。

## 8. 验收三项功能

1. **课程管控**：管理员打开“课程管理”，按教师、课程或课堂码搜索；进入其他教师的课堂，检查知识点、重点、难点和资料下载。可使用现有管理入口编辑内容、结束/重新开放收集，以及将课堂移入回收站并恢复。课堂归属不变；其他人的私人 MathAI 会话不开放。普通教师仍只能管理自己的课堂。
2. **四列课堂**：打开“我的课堂”，在宽度超过1000px的桌面窗口中每行4个；761–1000px为2列，760px及以下为1列。有至少4个课堂才能看到完整的一排。
3. **反馈分类**：打开课堂中的“学生反馈与答疑 → 谁遇到了什么问题？”。“有点疑惑”和“需要帮助”分别显示，桌面并排、手机上下排列。“听懂了”明细隐藏，但计入图表、CSV与答疑归档；不删除任何反馈。问题合计每页50份，学生更新状态后约5秒自动调整分组，网页需在前台。
4. 核对原账号、课堂、资料和历史答疑仍在。使用测试课堂和测试账号验收写操作，不要用真实教学课堂测试删除。

电脑按 `Ctrl+F5` 强制刷新；手机关闭旧页面后重新打开，避免继续显示旧资源。若有自建 CDN，再刷新相关页面及静态资源缓存。

## MathSig界面与跨课程MathAI更新验收

- 页眉、页脚及默认页面标题显示 MathSig，仓库名称和服务器目录仍沿用原值，无需改目录、数据库或Docker卷。
- 反馈区删除“谁遇到了什么问题？”及其两段说明，保留两个问题分类、分页和自动刷新。
- 课程学习空间删除“按板块学习与查阅资料”，知识点、重点、难点在桌面并排三列，手机单列。
- MathAI在关联课堂和已有会话中均跨课程检索当前用户有权访问的各教师文字模块，显示来源课程与教师。学生检索已加入的课堂，教师检索本人课堂，开发者管理员检索全站课堂；回收站内容不检索，也不读取其他学生的私密答疑。
- 使用外部模型时，只有明确勾选附带课程文字，才会发送相关模块；关联课堂为空时也可以跨课程检索。不识别图片/PDF/PPT，不保证生成式模型的答案一定正确。
