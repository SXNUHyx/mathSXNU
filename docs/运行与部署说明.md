## 维护文件

| 文件/目录 | 用途 | 处理方式 |
| --- | --- | --- |
| requirements.txt | 已安装版本的依赖锁定 | 纳入源码管理 |
| feedback/migrations/ | 数据库结构版本 | 纳入源码管理，上线前执行migrate |
| .local/db.sqlite3 | 课堂、反馈、账号、会话 | 不进入Git，定期备份 |
| .local/secret_key | 本地开发密钥 | 不进入Git，不在聊天中提供 |
| .local/screenshots/ | 自动化浏览器演示截图 | 演示数据，不用于声称真实教学成效 |
| staticfiles/ | collectstatic生成的静态资源 | 可以重新生成 |

日常启动：`bash scripts/start.sh`。首次安装或更新依赖/结构：`bash scripts/setup.sh`。安装会保留现有课堂数据，不会创建或重设教师账户。

## 教师账号

首次开通：`.venv/bin/python manage.py createsuperuser`，按提示填写；无需填写真实姓名。

忘记密码：维护者执行 `.venv/bin/python manage.py changepassword 用户名`，交互式设置，避免把密码写入命令行或仓库。

教师和学生现可在前端自行注册。注册时角色由服务器固定的教师/学生入口决定，不能通过额外表单字段授予管理员权限。所有教师只能查看本人创建的课堂，学生只能管理自己的课堂参与及反馈。

升级前的已有用户自动补充教师角色，超级管理员和维护人员保留原能力。升级后经程序手动创建的普通用户默认按学生处理，教师角色应通过教师注册入口创建或由维护者明确设置。普通教师注册不设置is_staff或is_superuser。

## 备份与恢复

执行 `.venv/bin/python manage.py backup_classroom`，使用SQLite在线备份API，避免运行时直接复制一个写入中的数据库。也可用 `--output 安全备份路径.sqlite3`，目标文件必须不存在。

至少每日备份一次，并保留服务器之外的一份副本。备份包含教师账户哈希和学生文字，不能公开上传。

恢复时：

1. 由维护者停止本应用服务，先备份当前数据库。
2. 用选定的备份替换实际数据库路径对应文件（默认 `.local/db.sqlite3`），恢复正确的服务用户读写权限。
3. 使用原生产密钥和设置，运行 `manage.py migrate --noinput`，再启动服务。
4. 登录核对课堂数量、反馈与导出。若会话无法沿用，重新登录，不修改学生数据补齐记录。

开发库没有真实数据时可使用临时数据库做恢复演练；不要在教学过程中覆盖正在使用的数据库。

## 正式部署交接（交给学校技术人员）

当前版本适合一位或少量教师的小规模试点。SQLite使用20秒超时和IMMEDIATE事务保护课堂关闭与反馈写入；仍需针对实际网络与班级规模验收，不承诺未经测试的并发能力。高并发、多实例部署需要改用PostgreSQL并重新测试事务行为。

建议：一台持久磁盘Linux服务器，HTTPS反向代理转发到仅监听本机端口的Gunicorn。依赖本地静态文件，不需要第三方CDN。可从2核4GB起测，依据负载结果调整。

生产运行必须注入：

- `DJANGO_DEBUG=0`
- `DJANGO_SECRET_KEY`：由维护者安全生成并保存在服务器密钥配置中，保持稳定，不填入源码。
- `DJANGO_ALLOWED_HOSTS`：实际域名，逗号分隔，不要使用任意主机通配符。
- `DJANGO_CSRF_TRUSTED_ORIGINS`：实际HTTPS站点来源（有跨来源需要时明确配置）。
- `DJANGO_DB_PATH`：持久数据库绝对路径，运行用户须可读写其所在目录。
- `DJANGO_TRUST_PROXY=1`：仅在可信反向代理覆盖X-Forwarded-Proto头，且Gunicorn只允许该代理访问时启用。

默认仍为HTTPS安全模式。只有明确开启 `CLASSROOM_SCHEME=http` 与 `CLASSROOM_ALLOW_INSECURE_HTTP=1` 的功能试用部署才使用非Secure Cookie并关闭默认HTTPS跳转。请使用[专门脚本和教程](HTTP公网IP登录修复.md)统一设置，不将HTTP试用作为正式教学部署。`check_login_access`命令可核对访问模式与Cookie设置，不输出密码或密钥。

关闭DEBUG后默认启用安全Cookie和HTTPS重定向。反向代理设置错误可能导致重定向循环，应检查代理头与实际TLS链路，不要关闭TLS验证解决。

在生产配置下运行安装、迁移、静态资源收集，然后启动：

```bash
.venv/bin/gunicorn mathsxnu.wsgi:application --bind 127.0.0.1:8000 --workers 1 --threads 4 --access-logfile -
```

由systemd等服务管理器负责重启和日志管理。WhiteNoise负责 `/static/`。可使用Caddy自动管理HTTPS，以下域名须换成实际域名：

```caddyfile
classroom.example.edu.cn {
    reverse_proxy 127.0.0.1:8000
}
```

教师登录已提供按用户名计数的失败冷却：同一账号10分钟内累计5次失败后，当前窗口内暂停尝试；它不替代学校网关的全站流量防护。

正式接入学生前完成：域名/学校审批、HTTPS、目标班级并发验证、备份恢复演练、数据留存说明和指定维护人。测试老师从最终域名登录，核对生成二维码中的地址，使用真实手机验证全流程。新手步骤见[零基础上线教程](零基础上线教程.md)。

## 课堂解释口径

红、黄、绿只表示学生当下自报状态，不是客观知识测验，不宜直接解释为课程目标达成率。

注册后反馈关联用户ID，使用账号稳定标识跨设备去重；前端不要求姓名、学号或手机号，也不提供实名资格验证。看板和导出不显示用户名，但管理员可通过数据库追溯。服务器访问日志也可能记录IP，应按学校要求减少日志留存。不同课堂导出使用各自随机编号，不导出账号稳定标识。

当前快照每个学生账号一行，历史每次实际变化一行；相同内容重试不新建历史。旧版不记名反馈继续保留，不能可靠认领给新账号，看板和CSV分别标注来源。混合新旧数据时须说明口径，不能把历史行数当作学生数。
