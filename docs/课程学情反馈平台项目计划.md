# mathSXNU：高等数学学习难点与教学反馈平台项目计划

编制日期：2026-11-01。本文件保留完整课程平台的建设计划。当前进度：已实现并在本地验证“课堂红黄绿灯反馈”第一版，操作见[项目说明](../README.md)；完整短测诊断、教学干预报告等仍为后续规划，尚未部署公网或开展真实学生试用。

## 1. 建设结论与边界

建议建设一个手机、电脑均可使用的小型网页平台，作为超星学习通的补充。核心任务是完成“发现难点—教师干预—再次检测—保存证据”的教学流程。

学习通继续承担课程资源、通知、常规作业、成绩和学校要求的教学记录；新平台聚焦知识点反馈、短测、难点分析和教学改进记录。第一版无需与学习通技术集成，可在学习通发布网页地址或二维码。实际能否直接打开取决于学校配置及客户端，应在试用前验证；始终保留复制到手机浏览器打开的入口。

项目目标是支持有证据的教学改进。平台本身不能保证通过一流课程评审，最终指标以本校当年申报通知和评分表为准。

默认试点：一位教师、一门高等数学或微积分课程、一个30—80人的班，先覆盖6个知识点。架构保留课程、班级维度；不把全校级并发、统一身份认证作为第一版目标。

第一版不建设：视频系统、完整教务系统、在线监考、自由手写证明自动评分、AI自动判卷、自动抓取学习通、复杂知识图谱和支付系统。

## 3. 路线选择

### 推荐：轻量定制网页，复用成熟通用组件

用Django构建前后端一体的小应用，沿用自己的mathSXNU仓库。理由：需要的特色是知识点、错因、教学干预和证据导出；把重型问卷或完整学习平台改造成这一流程，未必比做小应用更省维护成本。教师只使用后台与网页，不需要自己掌握前端工程。

替代路线：如果两周内必须开始真实收集，先在学习通现有问卷或校内已有LimeSurvey服务中采用本计划的反馈模板，按统一字段导出CSV，后续导入新平台。不要为了等网页开发而推迟教学数据收集，也不应同时长期运维多套系统。

后续扩展数学自动测评时再评估Numbas或STACK；不把它们同时纳入第一版。

## 4. 第一版使用流程与页面

### 教师端

1. 建立课程、班级、章节和知识点，导入班级内随机学生代码；首版由管理员开通教师账户，不开放公共注册。
2. 以模板创建一次课的活动，选择1—2个知识点，配3道短测题。
3. 发布限时加入链接和二维码；活动可关闭，避免长期开放。
4. 查看本次参与人数、反馈分布、逐题及知识点错误率、低信心正确与高信心错误人数。
5. 人工阅读学生困难描述，按概念理解、计算步骤、公式条件、建模转化等错因分类。
6. 记录采取的教学措施和对应知识点，发布结构相近的后测。
7. 一键导出原始记录CSV、知识点汇总CSV、教学干预日志和可打印教学改进报告。

### 学生端

1. 手机浏览器打开链接，输入班级随机学习代码和首次激活口令；后续使用安全会话。课程码只用于找到课程，不能作为访问个人记录的凭证。
2. 完成3道短测并选择答题信心：低、中、高。
3. 选择“能独立完成 / 听懂但不会独立做 / 有些跟不上 / 完全不理解”，勾选难点，选填一句话说明。
4. 提交后显示已保存、标准解析及教师发布的复习建议；个人仅能查看自己的练习记录。
5. 另设真正不绑定学习代码的匿名意见入口。匿名意见不能用于个人前后测配对，也不能保证一人一票。

### 页面清单

学生页面：加入班级、活动短测、难点反馈、提交结果、个人记录、匿名意见，共6类。
教师页面：课程与班级管理、活动发布、题库与知识点、学情看板、反馈处理与干预日志、报告导出，共6类。
首页只解释用途和入口，不堆叠与教学无关的功能。

## 5. 首轮试点内容

只做6个高频难点，例如：极限与函数值的区别、无穷小比较、连续与可导的关系、复合函数求导、定积分的意义、变上限积分求导。

每个知识点准备前测3题、平行后测3题，共36题；不是原题重做。题型以单选、判断为主，数值题仅在明确容差、输入格式、单位的前提下加入。第一版不接收任意数学表达式并声称能可靠判等。

每题必须填写：知识点、题干、选项、正确答案、解析、典型错误标签、难度、前后测组标识、题目版本、来源与使用权限。数学公式用LaTeX格式，由KaTeX或MathJax渲染；需验证移动端排版。

例题思路：对 f(x)=|x|，问“在x=0处连续”和“在x=0处可导”分别是否成立。错项可映射到“把连续当作可导充分条件”的误解。不要仅用“这题不会”作为错因标签。

开放意见不强制填写，课后反馈目标为1分钟左右，短测目标为3—5分钟。避免每节课重复冗长调查。

## 6. 指标与分析规则

| 指标 | 定义与使用方式 |
| --- | --- |
| 活动参与率 | 至少提交一次有效记录的学习代码数 / 本班当次应参与人数；非必填匿名意见不计算一人一票参与率 |
| 自述困难比例 | 选择“有些跟不上/完全不理解”的人数 / 本次有效反馈人数；同时显示分子、分母 |
| 逐题正确率 | 正确首答人数 / 本题有效首答人数；重复练习单独统计，不覆盖首答 |
| 知识点诊断 | 首版每道题一个主要知识点；按该知识点题目有效首答汇总正确率，同时显示样本数和题目数，避免一题多标签重复计数 |
| 高信心错误 | 回答错误且选择高信心的记录比例，用于提示可能存在稳定误解，须由教师复核 |
| 主观与客观交叉 | “自述听懂但短测错误”“自述困难但短测正确”作为关注线索，不直接给学生贴能力标签 |
| 前后测变化 | 用同一学习代码的有效配对样本计算后测正确率－前测正确率，以百分点表示；另报前测、后测和配对人数 |
| 反馈处理 | 未处理/已阅读/已采取措施/已复测；记录时间和教师说明 |

默认分析可只采用描述统计。样本足够且设计合适时，再由教师选择配对检验、置信区间或效应量。不同题难度、缺失样本和练习效应均会影响结果，不把单组前后差异直接说成因果效果；没有对照设计，不得宣称平台造成成绩提升。

不预设“提升20%”等结果性目标。技术验收目标和教学效果观察应分开。6个知识点的短测也不能代表整门课程的全面达成度。

## 7. 与评审材料的衔接

下表是通用材料组织建议，不是本校评分细则的替代物。取得实际评分表后逐项对应。

| 教学事实 | 可保存证据 | 可能支持的说明 |
| --- | --- | --- |
| 学生在某知识点集中出错 | 当次题目版本、错项分布、学生反馈、样本数 | 学情分析有依据 |
| 教师根据结果调整教学 | 带日期的干预日志、补充例题、课堂活动说明 | 以学生学习为中心和持续改进 |
| 使用结构相近的题复测 | 前后测题目、有效配对数、结果与缺失说明 | 教学成效的观察与反思 |
| 组织概念辨析、推理或应用 | 经教师审定的题目与学生匿名作品 | 为高阶性、创新性、挑战度提供实际案例，而非仅展示界面 |
| 持续使用并修正教学安排 | 多次课程记录、版本和导出报告 | 课程建设过程可追溯 |

首轮建议形成：1份学情分析报告、2个完整改进案例、1份学生反馈摘要、1份使用与局限说明。若已有历史教学记录可一并整理，但不可把模拟数据、演示截图或尚未实施的活动写成真实成效。完整学期材料应随真实教学继续积累，4—6周试点不足以替代学校可能要求的长期建设周期。

## 8. 实施技术方案

建议技术：Python 3.12、Django 5.2 LTS系列的受支持补丁版本、Django模板、少量JavaScript、数学公式渲染库和Chart.js。开发环境可用SQLite；上线使用PostgreSQL。Django Admin承担基础数据维护，另做易用的活动发布与看板页面。无需第一版同时学习React/Vue和独立API服务。

生产部署：一个学校提供的Linux虚拟机，运行应用、PostgreSQL和HTTPS反向代理；可封装成Docker Compose，由技术协助者维护。浏览器→HTTPS反向代理→Django→数据库。前台不保存数据库密码或教师权限令牌。

建议试点资源起点：2核CPU、4GB内存、40GB磁盘；仅是采购估算，不代表并发保证。先用目标班规模模拟同一时间提交，再决定是否扩容。数学渲染与图表等静态资源随站点发布，避免课堂依赖外部CDN。

部署顺序：开发机使用虚拟环境→本地功能与权限检查→测试服务器使用合成数据→迁移数据库和收集静态文件→配置域名与HTTPS→备份恢复与负载检查→真实班级试用。开发服务器不能直接用作公网生产服务。

服务器位置优先学校机房或学校认可的国内云服务。若使用境内公网域名，提前按服务商与学校要求核对备案及相关手续。内网部署须确认学生实际可访问。GitHub用于保存代码和文档；GitHub Pages只能承载静态页面，不能单独支撑本方案的登录、共享数据和教师权限。

### 最小数据模型

- Teacher：教师账户、角色及状态。
- Course/Class：课程、学期、班级、任课教师；所有教师查询按所属课程隔离。
- Enrollment：班级内随机学习代码、凭据摘要、状态；学号对应表由教师线下保管，不进入公开仓库。
- KnowledgePoint：章节、知识点代码、名称、学习目标。
- QuestionVersion：题干、选项、答案、解析、主要知识点、错因标签、版本、来源。
- Activity：课程活动、开始/截止时间、前后测配对组、题目版本集合、发布状态。
- Attempt/Answer：学习代码、活动、作答轮次、答案、信心、得分、提交时间；保存首答及历史，不覆盖。
- Feedback：活动、学习代码或匿名类型、理解程度、难点类别、选填文字、处理状态。
- Intervention：知识点、触发证据、措施、日期、后测活动、教师反思。
- ExportLog：导出人、范围、时间、报告版本。

报告导出包含：课程/班级、活动日期、题目版本、样本口径、前后测及配对人数、结果、干预措施、缺失说明、生成时间。对同一数据快照导出的结果必须可复算。

## 9. 权限、数据与日常运维

1. 教师账户密码哈希存储；学生使用不可猜测的独立凭据与安全会话；课程码不授予教师权限。限制登录和提交频率，活动提交做幂等处理，避免重复统计。
2. 页面隐藏答案不等于保护答案：测验提交前，答案与解析不得出现在学生可获取的数据中。教师页面、API和导出均做服务端权限检查。
3. 具名或可配对的学习记录与真正匿名意见分开。随机代码可重新关联到学生时仍属于可识别个人的数据。收集前说明用途、可见范围、保存期限和联系渠道；不公开班级成员明细。
4. 只收教学所需信息，不采集身份证号、手机号、人脸。说明匿名入口仍可能产生访问日志，尽量减少日志留存，不宣称技术上绝对不可追踪。
5. 配置CSRF保护、模板转义、安全Cookie、HTTPS和DEBUG关闭；文本按纯文本呈现。CSV导出处理公式注入风险。
6. 每日自动备份数据库，至少留一份与服务器分离的加密副本；正式试点前做一次恢复演练，目标为最多损失一天数据、一个工作日内恢复。具体能力以演练结果为准。
7. 默认建议保留一个教学年度，期满按学校规定清理或去标识；正式期限由学校制度确定。评审公开材料只展示聚合结果和脱敏案例，小样本避免识别个人。
8. 初版不向外部AI服务发送学生原始反馈。未来若做文本归类，先核对学校要求、数据处理方式和人工复核流程。
9. 明确一名维护联系人；每月检查依赖安全更新、磁盘、备份和错误日志。服务器、域名和源码应归学校/课程团队管理，避免完全依赖某个学生的私人账号。

## 10. 六周实施计划与责任

下列工期假设有一位熟悉Python网页开发的协助者每周投入约15—25小时，教师每周投入约2—4小时；开发估算80—140小时，可能因学校审批或数据要求延长。零基础教师独自从零完成，不应承诺同样周期。

| 阶段 | 教师负责 | 技术协助者负责 | 可验收结果 |
| --- | --- | --- | --- |
| 第1周：需求与教学内容 | 提供评审评分表、确定试点班和6个知识点、审定反馈模板 | 页面原型、数据模型、部署位置和权限设计 | 明确功能边界；一份真实课程活动样例，不填造学生数据 |
| 第2周：最小可用流程 | 完成首批18道前测题及解析 | 教师登录、课程班级、学生凭据、题库导入、活动发布和提交 | 手机能打开并提交，教师能看到已落库记录 |
| 第3周：诊断与导出 | 审定错因标签和看板口径，准备18道平行后测 | 统计看板、反馈处理、干预记录、CSV和打印报告 | 用预先手算的合成数据核对统计结果 |
| 第4周：上线准备 | 邀请5—10名志愿者试用，确认说明文案 | HTTPS、权限与并发测试、备份恢复、部署与维护手册 | 完成上线验收；合成与试用数据明确标识 |
| 第5—6周：教学试点 | 一个班真实使用，完成至少2轮干预—复测，记录局限 | 处理缺陷，保障可用性和导出 | 真实教学案例与初步分析报告；继续按学期积累 |

遇到课表变化或收集不到配对数据，应调整试点周期并如实记录，不以补造数据追赶排期。

## 11. 上线验收清单

以下为将来必须执行的验收，不是已经通过的测试：

- [ ] 学生用手机完成加入、短测、反馈、提交与结果查看；弱网重试不重复计数。
- [ ] 只有教师能发布活动、查看班级明细及导出；学生A不能读学生B记录，教师A不能读教师B班级。
- [ ] 未提交前无法从页面源码或接口取得正确答案；截止活动不能继续提交。
- [ ] 前测/后测与首答/重答记录区分明确；匿名意见不能错误地加入配对分析。
- [ ] 用手工可复算的数据核对参与率、正确率、分母、缺失和配对结果；包括无人提交和仅部分人提交场景。
- [ ] 数学公式、中文输入和图表在常用手机浏览器显示正常；学习通内打开失败时可复制到浏览器使用。
- [ ] 针对试点目标模拟80名学生在60秒内各提交一次；无记录丢失或重复。设定提交接口95%响应时间小于3秒的试验目标，实际测试后记录服务器配置与结果，不提前声称达标。
- [ ] 数据库备份可恢复，重启服务器后记录仍在，导出文件能正常用Excel和统计软件读取。
- [ ] 测试环境与演示数据不混入真实教学报告；导出进行权限和脱敏检查。
- [ ] 代码、部署文件、题库模板、使用手册、维护联系人和服务器权限交接齐全。

## 12. 经费与采购建议

下列仅为规划估算，不是商家报价：已有校内服务器时可大幅降低新增支出。自购小型云服务器约80—250元/月，域名约50—150元/年，异地备份和存储约0—50元/月；按12个月粗算基础设施约1,010—3,750元/年，价格随地域、续费、带宽和优惠变化。HTTPS可选择免费证书，仍需要自动续期与维护。

开发人工单独计算：预计80—140小时，按学校助研、项目制或供应商实际费率询价；不能把“开源免费”等同于无开发和维护成本。正式委托前按本计划验收清单取得书面报价，并约定缺陷修复期、数据所有权和交接。

优先顺序：学校提供服务器与技术协助＞校内学生团队在教师指导下开发并指定长期维护人＞小额委托开发。不建议零基础教师先购买大量云服务或多个商业系统，再寻找使用场景。

## 13. 可直接启动的工作包

教师本周可完成：取得学校评审评分表；选定一个班；确定6个知识点；填写18道前测题；用附录反馈模板开始一次小规模调查。教师的主要投入是教学设计和题目审核。

技术实施首个里程碑：在mathSXNU仓库实现“教师建活动→学生提交→教师看知识点汇总→导出CSV”的完整流程。当前已完成交通灯反馈的建课、提交、实时汇总与CSV导出；下一阶段再扩展题库短测、知识点诊断、干预日志、后测与报告。现有云环境和检出可继续用于开发。

交付物：完整源码与依赖锁定文件、数据库迁移、示例配置（不含密钥）、测试、部署文件、教师操作手册、学生简明说明、题库导入模板、备份恢复手册、匿名化演示数据、统计口径说明。测试账户与真实账户分开。

## 附录A：每课反馈模板

非匿名教学反馈（课堂活动自动带入，不要求学生重复输入）：

1. 对本次知识点的掌握程度：能独立完成 / 听懂但不会独立做 / 有些跟不上 / 完全不理解。
2. 最困难的知识点：从本次教师发布的知识点中选择，最多2项。
3. 困难类型：概念含义 / 公式适用条件 / 计算步骤 / 图像理解 / 文字转数学 / 其他。
4. 请用一句话写出卡住的位置（选填）。
5. 希望下一次如何帮助：补充基础例题 / 再讲关键步骤 / 讲解典型错误 / 小组讨论 / 暂不需要。

短测的每题另外记录答案和答题信心。匿名意见另开入口，注明“不用于个体学习追踪，请勿填写姓名、学号或他人隐私”。

## 附录C：首版风险与应对

- 学生不愿反馈：每次控制时间、说明不因负面反馈扣分；允许匿名意见，不把参与率当作唯一效果指标。
- 题目不等价：教师先审平行题；报告注明难度差异，不只展示分数涨幅。
- 反馈过多：优先结构化选择，每课选一个主要问题闭环，不把文本自动分类当作可靠结论。
- 账号或链接泄露：活动限时、凭据可撤销、教师权限独立；异常提交人工复核。
- 服务器或维护人离开：源码与资源归团队、异地备份、交接手册；紧急时恢复学习通原有教学流程。
- 评审时间太近：先整理已有真实教学材料并启动反馈收集，网页功能分期；不承诺短期内产生长期建设成效。
