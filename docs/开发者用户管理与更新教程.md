# 开发者用户管理：使用与原服务器更新教程

**腾讯云后续更新请使用[已验证的IPv4更新流程](课程管理与反馈分组更新教程.md#3-拉取-github-新代码沿用本次服务器验证成功的-ipv4-流程)，解决普通Git连接GitHub-443超时的问题，原备份与数据卷保留步骤继续有效。**

现在可以在网页中管理全平台账号。数据库沿用服务器已经使用的 **SQLite**，账号、密码散列和教学数据继续保存在原持久卷；本次无需安装 MySQL，也无需安装 Node.js、Vue 或 React。后台与原网站共用登录和部署，使用中文界面，支持 Windows、安卓、iOS、macOS 的现代浏览器。

## 一、你更新后会得到什么

| 功能 | 操作效果 |
| --- | --- |
| 全站账号列表 | 查看用户名、姓名、学号、角色、状态、注册和最后登录时间；分页、搜索、角色和状态筛选 |
| 创建账号 | 创建中文用户名的学生、教师或开发者管理员，初始密码经过散列存储 |
| 修改资料和角色 | 修改账号姓名、学号、邮箱及角色，用户名固定，历史反馈身份快照不改写 |
| 停用 / 启用 | 停用后不能登录，已有会话后续请求也被拒绝；可以再次启用 |
| 重置密码 | 设置新密码，使原密码和旧登录会话失效；学生和教师也可从导航栏自行修改密码 |
| 归档 / 恢复 | 归档后不能登录，课堂、反馈、文件、答疑与AI记录保留；恢复后保持停用，核对后另行启用 |
| 用户导出 | 按当前筛选条件导出CSV，学号前导零在文件中保留；Excel打开时将学号列按文本导入 |
| 操作日志 | 查询管理员对账号的创建、修改、启停、归档、恢复和重置密码记录及变更前后资料 |

后台入口是原网站地址后加 `/developer/`。普通教师、学生和仅有 `is_staff` 的账号不能进入。开发者必须同时具有启用状态、`is_staff` 和 `is_superuser`；前端注册绝不会自动获得这些权限。

当前登录的管理员不能停用、归档或降低自己的角色。名下有课堂（包括课堂回收站）的教师不能直接改为学生，以免失去教学入口。本次采用可恢复归档，不提供永久删除账号或课堂归属转移。

账号资料未经学校自动核验；修改它们不会改写此前课堂中填写的姓名、学号。后台管理的是账号，不额外开放其他人的私人MathAI会话内容。密码和密码散列不通过管理接口或自动审计字段返回；操作备注中也不要手动填写密码、验证码或API密钥。

## 二、在原服务器更新：每组成功后再执行下一组

打开原来的 Ubuntu 云服务器终端。下面命令全部在服务器执行，不是在 Windows 的命令提示符执行。更新会短暂中断网页访问，请选择没有上课的时间。

### 第1步：进入原项目，检查数据位置

```bash
cd /opt/mathsxnu
sudo git status --short
sudo docker compose ps
sudo docker compose exec -T web python -c "import os,django; os.environ.setdefault('DJANGO_SETTINGS_MODULE','mathsxnu.settings'); django.setup(); from django.conf import settings; print(settings.DATABASES['default']['NAME'])"
sudo docker inspect mathsxnu-classroom-web-1 --format '{{range .Mounts}}{{println .Type .Name .Destination}}{{end}}'
```

正常应看到数据库 `/data/db.sqlite3`，挂载包含 `volume mathsxnu-classroom_classroom_data /data`。若不一致，先核对原数据库路径和卷；不要换一个目录重新部署，否则可能看到空账号列表。

`git status --short` 没有输出表示代码干净，可以继续。如果仍有您曾经修改过的 `compose.yaml`、`deploy/Caddyfile`、`mathsxnu/settings.py`，先按[原三处配置的备份与暂存步骤](课程学习与答疑六项功能更新.md#先处理您之前的本地改动)处理。其他未知改动先备份并核对，不执行 `git reset --hard`。保留原 `.env`，无需重新运行首次部署向导。

### 第2步：先备份数据库和上传资料

```bash
sudo bash scripts/backup-server.sh
```

应提示备份已保存到 `backups/`，包括 `.sqlite3` 数据库及资料压缩包。更早没有上传功能的版本仅备份数据库。备份失败就先停止更新。建议另外下载一份备份到自己的电脑安全保存。

### 第3步：下载新代码、构建新版

```bash
sudo git pull --ff-only origin main
ls feedback/migrations/0009_user_management.py
sudo docker compose build web
```

应能看到 `0009_user_management.py` 文件。若提示 `Already up to date` 但没有该文件，请检查是否拉取了 `SXNUHyx/mathSXNU` 的 `main`，不要继续重建旧代码。构建失败时旧网站仍可运行，先处理构建错误。

原网站已经可以正常登录时，保留现有HTTP/HTTPS和域名配置。如果您仍停留在早期 `ba020ae`，且刚按旧教程暂存了三处手工HTTP配置、尚未写入新版访问模式，可在构建前执行：

```bash
sudo python3 scripts/set-access-mode.py --http-trial --host 152.136.110.150
```

仅在仍使用该公网IP的HTTP试用时执行这一条；已使用HTTPS域名不执行。正式管理真实师生账号应使用HTTPS，沿用[上线教程](零基础上线教程.md)的域名与证书步骤。HTTP试用仍只使用测试数据。

### 第4步：暂停网页入口，再备份一次

```bash
sudo docker compose stop gateway
sudo bash scripts/backup-server.sh
```

这次备份覆盖构建期间新增的资料和反馈。如果备份失败且尚未启动新版，可执行 `sudo docker compose start gateway` 恢复旧入口，先排查备份。

### 第5步：启动新版并检查迁移

```bash
sudo docker compose up -d --no-build --force-recreate --wait --wait-timeout 180
sudo docker compose ps
sudo docker compose exec -T web python manage.py showmigrations feedback
sudo docker compose exec -T web python manage.py check_login_access
```

正常应看到 `web` 为 `healthy`，`gateway` 为运行状态，以及 `[X] 0009_user_management`。容器启动脚本会自动迁移；这次仅增加账号归档时间字段和管理日志表，不删除原账号，不更换数据库，不自动提升任何人的权限。

若失败，运行：

```bash
sudo docker compose logs --tail=80 web gateway
```

保留备份和原持久卷，不执行 `docker compose down -v`，不自行反向迁移。分享错误信息时隐藏个人资料，不发送 `.env` 或密码。如果日志显示 `Unknown command`，通常仍运行旧镜像，需要确认第3步拉取和构建成功。

## 三、给自己开通开发者管理员

只能通过有服务器终端权限的维护者开通第一个管理员。下面两种方法选择一种即可。

### 方法A：您已经有自己的登录账号（推荐）

把下面引号里的文字换成您**实际登录时输入的用户名**，保留英文双引号。它不是学生反馈时填写的姓名。

```bash
sudo docker compose exec -T web python manage.py grant_platform_admin --username "您的实际登录用户名"
```

看到“已开通开发者管理员权限”即可。这个命令不改变原密码；会启用账号、清除归档标记并将其设为开发者管理员，记录“服务器终端开通管理员”日志。它会保留您原有的课堂。

### 方法B：新建一个独立管理员账号

```bash
sudo docker compose exec web python manage.py createsuperuser
```

按照提示依次填写用户名、邮箱（可留空）、密码及确认密码。输入密码时屏幕不显示字符，是正常情况；请使用强密码，不接受弱密码绕过提示。不要把密码发到聊天或提交GitHub。

如果不小心忘记管理员密码，只有服务器维护者可以在终端重设：

```bash
sudo docker compose exec web python manage.py changepassword "您的实际登录用户名"
```

## 四、打开后台，按按钮管理用户

1. 在 Windows 浏览器中打开原网站并登录自己的管理员账号。
2. 点击顶部“开发者管理”，或在地址栏输入原网站地址后加 `/developer/`。仍使用原IP时就是 `http://152.136.110.150/developer/`；已绑定HTTPS域名则使用自己的HTTPS地址。
3. 若没有出现入口，先退出再登录；核对第3节命令是否针对正确用户名执行。普通教师不应该看到这个入口。
4. 在搜索框输入用户名、姓名、学号或邮箱，点击“搜索用户”。也可以选择“教师 / 学生 / 开发者管理员”和账号状态。
5. 点击目标账号旁边“查看 / 管理”。修改姓名、学号、邮箱或角色后，点击“保存账号资料”，确认后生效。
6. 需要暂时限制账号，点击“停用账号”，在确认页核对用户名，再点击“确认停用账号”。需要恢复使用时点击“启用账号”并确认。
7. 毕业或离校账号可点击“归档账号”，核对后确认。以后在列表筛选“已归档”，进入账号点击“恢复账号”；恢复后核对资料，再单独启用。
8. 用户忘记密码时，点击“重置密码”，输入两遍新密码并确认。通过私密方式通知本人，让其登录后点击“修改密码”。这里没有短信或邮箱自动找回功能。
9. 点击“导出筛选用户CSV”可下载名册；点击“操作日志”查询谁在什么时候修改了哪个账号。

安卓手机使用相同网址和账号。后台表格可以在表格内部左右滑动；无需安装App。Windows更新后按 `Ctrl+F5`，安卓关闭旧网页重新打开，避免读到旧样式。

## 五、上线验收：先使用测试账号

1. 核对原账号、课堂、上传资料、学生反馈、教师答疑和MathAI旧会话仍然存在。
2. 使用普通教师和学生登录，确认看不到“开发者管理”，直接打开 `/developer/` 也不能访问。
3. 管理员创建一个中文用户名的测试学生，填写带前导零的学号，确认列表可搜索。
4. 在另一浏览器登录该测试学生，再从后台停用它；刷新学生页面应要求重新登录。启用后原密码可用。
5. 对测试账号执行归档、恢复、启用，核对原数据仍在。
6. 重置测试学生密码，确认旧密码不能登录，新密码能登录，旧设备会话失效。
7. 检查操作日志和CSV；不要用真实教学账号测试归档或角色降级。

本次自动化验证使用临时数据库和虚构数据，包含138项Django测试（含旧库升级保留数据），以及真实Chromium中的后台流程、接口搜索/CSRF写入、CSV下载、手机布局和原教学流程回归。您的服务器仍需按本教程更新后才会生效。

## 六、后端接口（给后续开发者）

前后端采用同域Django会话认证，写接口要求CSRF令牌和 `Content-Type: application/json`。所有接口都要求开发者权限，没有公开匿名管理API，也没有默认API密钥。返回值不含密码散列、会话或学生私有问题正文。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/developer/api/users/` | 分页用户列表及全站数量统计 |
| POST | `/developer/api/users/` | 创建账号 |
| GET | `/developer/api/users/用户ID/` | 账号详情及名下/加入课堂数量 |
| PATCH | `/developer/api/users/用户ID/` | 修改资料、角色；未提供字段保留原值 |
| POST | `/developer/api/users/用户ID/actions/` | 启停、归档、恢复、重置密码 |
| GET | `/developer/api/audit/` | 只读管理操作日志 |

列表参数：`q` 搜索用户名、姓名、学号、邮箱；`role=student/teacher/admin`；`status=active/inactive/archived`；`page` 从1开始；`per_page=25/50/100`，默认25。日志支持 `q`（操作者/目标用户名）和 `page`，每页25条。页码超出范围回到最后一页。

创建字段：`username`、`password1`、`password2`、`role` 必填；`real_name`、`student_number`、`email`、`reason` 选填。角色限上述三种，不接受 `is_staff`、`is_superuser` 等原始权限字段。

修改字段：`real_name`、`student_number`、`email`、`role`、`reason`，并要求 `confirm: true`。用户名不可修改，所有JSON写入拒绝未定义字段。操作字段为 `action`（`enable/disable/archive/restore/password_reset`）、`confirm: true` 和可选 `reason`；密码重置再提供 `new_password1`、`new_password2`，重置自己还必须提供 `current_password`。

在已登录管理员的同源网页中，可按以下方式调用；示例仅查询停用用户，不修改数据：

```javascript
const response = await fetch('/developer/api/users/?status=inactive&page=1', {
  credentials: 'same-origin',
  headers: {Accept: 'application/json'}
});
const result = await response.json();
```

写操作从页面表单的 `[name=csrfmiddlewaretoken]` 读取令牌，放入 `X-CSRFToken` 请求头。不要关闭CSRF验证。成功列表返回 `{ok, users, pagination, counts}`；详情/变更返回 `{ok, user}`；创建返回201，其余成功200。常见错误：401未登录、403权限不足/CSRF失败、404用户不存在、400参数或业务校验失败、405方法不允许、413请求体过大。JSON写入限制64KB；密码遵循现有Django校验并散列保存，既不会返回原密码，也不会以明文存储。

SQLite适合当前单机小平台；本次没有增加数据库连接成本。若将来需要多台服务器或更高并发，可另行规划MySQL迁移并验证数据转换，不能直接切换连接参数就认为原数据已迁移。

项目中的软著材料压缩包仍是此前冻结的 `ffe42a8` 代码快照，**不包含本次开发者后台**。如需将新功能纳入登记材料，应重新生成代码页、截图和手册，并核对实际版本与完成日期。
